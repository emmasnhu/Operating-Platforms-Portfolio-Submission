# Operating-Platforms-Portfolio-Submission
This is my submission for Southern New Hampshire University's CS 230 class on Operating Platforms.

**Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?**
The Gaming Room is a client that asked for help setting up the environment for their game "Draw It or Lose It." Their game was initially only available on Android, but they wanted their game to be a cross platform web application. 

**What did you do particularly well in developing this documentation?**
I think I did a nice job with writing the first part of the document. I think I went into nice detail in the executive summary, the requirements, and design constraints. I also think I identified a lot of development tools that would be beneficial for each operating platform to use if they were to develop this project.

**What about the process of working through a design document did you find helpful when developing the code?**
I found the process of working through a design document helpful when developing code because it helped break down the project to be more understandable. The Domain Model and UML Diagram in the beginning was particularly helpful for developing code. Then when I had to write about the client and server side, it helped me understand why I was coding the things the assignment asked for. 

**If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?**
I think I would pick the "Mobile Devices" column in the Evaluation chart. I didn't know much about development for mobile operating platforms when writing it and I think I would improve it by doing more research and going into greater detail. 

**How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?**
It is important to consider the user's needs when designing because the entire application is supposed to be catered to the user. If a user does not have their needs met, they will not play the game and the client will likely lose money and be disappointed. For this project, I interpreted the user's needs by looking at what The Gaming Room wanted to implement. In the future, The Gaming Room can collect reviews and feedback from users and turn that feedback into user stories to help improve the game. 

**How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?**
I mainly approached designing software through making UML templates. This helped me design what the software should look like before wasting time coding it and then realizing a flaw in the design. I would use this approach in the future, and I would also like to explore designing more of the user interface in the future.
